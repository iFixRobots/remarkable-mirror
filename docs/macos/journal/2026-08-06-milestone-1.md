## Lessons and remaining checks

- A macOS destination alone did not constrain the Release architecture set;
  the target needed an explicit `ARCHS = arm64` policy.
- A private SwiftUI view initially missed a required model dependency during an
  accessibility refactor. The focused build caught it before packaging.
- Querying window bounds through System Events raised an unexpected Apple
  Events consent sheet. The request was not approved; later acceptance checks
  used the app accessibility surface and read-only Core Graphics window
  metadata instead.
- Real first-open smoothness, mid-animation reversal, rapid repeated toggling,
  high-refresh motion, VoiceOver traversal, accessibility display variants and
  physical mixed-display behavior remain owner/manual checks.
- No tablet authentication, frame, input, screenshot, document, Files, wake or
  handoff path exists in this milestone. No tablet state was changed.
- The Windows x64 build and focused PowerShell policy checks cannot run on this
  macOS host and remain unrun here.
- No commit, push, Developer ID signing or notarization was performed.

```zsh
  'artifacts/macos/DerivedData/Build/Products/Release/reMarkable Mirror.app/Contents/Info.plist'
lipo -archs \
  'artifacts/macos/DerivedData/Build/Products/Release/reMarkable Mirror.app/Contents/MacOS/reMarkable Mirror'
codesign --verify --deep --strict \
  'artifacts/macos/DerivedData/Build/Products/Release/reMarkable Mirror.app'
unzip -t \
  artifacts/macos/package/reMarkable-Mirror-0.1.0-macOS-arm64-unsigned.zip
```

The final `codesign --verify --deep --strict` command is expected to fail for
this deliberately unsigned local bundle. The package script uses that result
to avoid mislabeling the executable's linker-generated ad-hoc signature as a
valid app-bundle signature.
